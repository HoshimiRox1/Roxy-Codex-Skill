# SKILL介绍

## Visualize

这个 skill 实现类 claude.ai 功能的可视化图表和交互知识块的功能。
他能实现的功能有：
- 流程图
- 架构图
- 时序图等等图
- 交互知识块

但该skill是专门为了obsidian记笔记服务的
默认生成的图回答是obsidian搭配dataview插件的笔记。图和交互块将插入在dataviewjs代码块内
若指明生成在桌面，则输出html或svg文件
其他输出目录和文件情况可自己指明

> [!tip] 便捷使用
> 为了更好地触发这个skill，内部的 `AGENTS.md` 建议放在.codex根目录下，实现全局规则管控

> [!caution] 路径注意
> 因为默认是输出到我本机的obsidian文件夹。
> 所以他人使用时需要修改输出路径。
> AGENTS.md、SKILL.md等地方都有输出路径的指示，所以建议直接让codex找出来修改就行

## atomic-explainer

这个 skill 用来做「原子化解释」，专门处理新术语和抽象概念。
适合用户说“听不懂”“讲细一点”“一步步解释”的场景。

默认解释方式是：
- 它是什么
- 它在当前机制里起什么作用
- 它不是什么（和相邻概念如何区分）

## doc

这个 skill 用来处理 `.docx` 文档的读取、创建和修改，重点是排版和视觉一致性。
推荐配合 `python-docx` 做结构化编辑，并通过渲染检查最终版式。

适合场景：
- 实验报告、说明文档、交付文档的排版整理
- 表格、分页、标题层级需要精修的文档任务

---

## pdf

这个 skill 用来处理 PDF 的阅读、生成和评审，强调“先看渲染结果再结论”。
推荐用 Poppler 做页面渲染检查，用 `reportlab`、`pdfplumber`、`pypdf` 做生成/提取。

适合场景：
- 需要核对布局、图表、字体可读性的 PDF 交付
- 基于 PDF 的内容抽取和质量评审

---

## playwright

这个 skill 用来在终端里自动化真实浏览器流程（打开页面、点击、填表、截图、抓取信息）。
默认走 `playwright-cli` 和 skill 自带 wrapper 脚本，不强制写测试项目。

常见用途：
- 复现/排查网页交互流程问题
- 批量截图、页面状态采集、UI 流程验证

---

## quiz

这个 skill 用来生成自包含 HTML 互动测验（单选、多选、判断、填空）。
默认从网络资料出题，只有用户明确要求时才基于本地笔记出题。

输出特点：
- 默认保存到 Windows 桌面并自动打开浏览器
- 带即时反馈、得分统计、计时和题目顺序打乱
